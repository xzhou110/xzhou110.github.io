A Key DecisionExtract repeated infrastructure only after multiple apps need it.

The Case Study

Problem
Several local apps needed the same file safety, request validation, and recovery behavior. Maintaining separate copies made a fix easy to miss in one consumer.
What I Built
A small, versioned library for atomic JSON writes with ETags, a guarded static server, server-sent events, and single-server locking, with no runtime dependencies.
How It Works
Shared mechanisms sit behind explicit interfaces while each app keeps its own domain logic. Real-socket parity tests check that extracting the shared implementation preserves consumer behavior.
Where It Stands
Version 0.1.0 is released and used by AI Usage Tracker. Other planned consumers have not yet migrated; this is an incremental extraction.
Evidence and Limits
  • Parity tests check consumer behavior through actual HTTP sockets.
  • One application has migrated. The package is not presented as a completed migration of every local app.
  • Localhost guards and conflict checks address specific risks; they are not a claim of absolute security.
